Person-managed authorization, in a page

This page walks one consent loop with the LifeCare.ID® sandbox as the authorization server: discover, be challenged, ask the person, exchange the code, read, and see the person revoke. The requests below are the live ones.

A sandbox walk with a synthetic person. The person is made for this run and has no data of their own; the source returns synthetic personas. Nothing here is production, and nothing here is a real person's record.

    2. The challenge
    
      
    A request with no token is answered with a 401. Its WWW-Authenticate header names the metadata and the scope to ask for.

    3. The person's yes
    
      
    The authorization request carries a PKCE challenge and the source as the resource. A real person taps a passkey on the LifeCare.ID® origin. Here the sandbox accepts the synthetic person's session in its place, posted by the backend, and the browser receives the redirect in a hidden frame of this page.

  4. 
      
    4. The exchange
    
      
    The page posts the code and its PKCE verifier to the backend. The backend adds the client secret, which the page never holds, and keeps the token. The page gets the token cut to ten characters.
    
      
    
      
    
    
    5. 
    
  5. 
      
    5. The read, the receipt and the revoke
    
      
    The backend reads the source with the token. The source checks the token at the sandbox, writes a line in the person's ledger, then answers with the data and a receipt. After the person revokes, the very next read is refused.
